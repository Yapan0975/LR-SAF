# Cross-validation and train/val split protocol

This note documents the exact data splits used for the YorkUrban (YUD) experiments
so that every reported number can be reproduced. All splits are defined over the
**102 YorkUrban images** (indices `0..101`, in the canonical dataset ordering).

## 5-fold cross-validation (CV sAP tables)

The 5 folds are produced by a single deterministic call:

```python
import numpy as np
folds = np.array_split(np.random.RandomState(0).permutation(102), 5)
```

- `numpy.random.RandomState(0).permutation(102)` gives a fixed shuffle of the 102 image indices.
- `numpy.array_split(..., 5)` splits that permutation into 5 contiguous groups.
- Because 102 is not divisible by 5, the fold sizes are **21, 21, 20, 20, 20** (sum = 102).

Each fold is used once as the held-out test set:

- For every fold `k` we run **one** fine-tune on the other four folds (the training images).
- The **final-epoch** model from that fine-tune is then scored on the held-out fold `k`.
- We do this independently for each of the four conditions reported in the CV tables:
  `afm_bb`, `lrsaf_bb`, `afm_head`, `lrsaf_head` (backbone vs. confidence-head, AFM vs. LR-SAF).
- Per-image predictions, ground truth, and per-image scores for each (condition, fold)
  pair are stored in `../predictions/cv_sap/<condition>_fold<k>.json`.

The materialised fold indices are stored in `cv_fold_indices.json` (a list of 5 lists of
image indices), generated by:

```python
import numpy as np, json
idx = [a.tolist() for a in np.array_split(np.random.RandomState(0).permutation(102), 5)]
json.dump(idx, open('configs/cv_fold_indices.json', 'w'), indent=2)
```

## Main 80 / 22 train/val split

For the single-split experiments (main sAP table and ablations) we use a fixed
80 train / 22 val partition of the same 102 images:

```python
import numpy as np
perm = np.random.RandomState(42).permutation(102)
train_idx = perm[:80]   # first 80 -> training
val_idx   = perm[80:]   # last 22  -> validation / held-out
```

- Seed is `42` (distinct from the CV seed `0`).
- The **first 80** permuted indices are the training set; the **last 22** are the held-out
  validation set.
- This 80/22 split backs the aggregate numbers in `../predictions/main_table_sap.json`.

## Reproducing

Run the snippets above (NumPy only) to regenerate the indices and confirm they match
`cv_fold_indices.json`. The CV runners are in `../scripts/run_cv*.sh`; the standard
dataset-level sAP evaluator is `../metrics.py` (`image_records` + `sap_dataset`).
